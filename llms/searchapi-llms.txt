# SearchApi

> SearchApi is a real-time SERP and search-data API that gives applications and AI agents structured JSON access to results from 100+ search engines — Google Search, Maps, News, Scholar, Images, Shopping, Trends, Jobs, Patents; YouTube, Bing, Baidu, Yandex, DuckDuckGo; marketplaces like Amazon, Walmart, eBay and BestBuy; travel surfaces like Google Flights, Google Hotels and Airbnb; and answer engines like ChatGPT, Gemini and Perplexity. It handles proxy rotation, CAPTCHA solving, and geographic/locale targeting server-side, and ships a hosted MCP server plus configurable tool "bundles" so agents can be handed a capability instead of a whole catalog.

## API
- Base URL: https://www.searchapi.io/api/v1/search (single endpoint, parameterized by `engine`)
- Methods: GET and POST. POST (added January 2026) takes the same parameters as a JSON body.
- Auth: `Authorization: Bearer <API_KEY>` header (preferred) or `api_key` query param
- Required params: `engine`, `q`. Common: `location`/`uule` (mutually exclusive), `gl`, `hl`, `device`, `page`, `time_period`, `safe`, `filter`, `verbatim`
- Response: JSON with `search_metadata`, `search_parameters`, `search_information`, `organic_results`, `pagination`, plus engine-specific blocks (`answer_box`, `knowledge_graph`, `ads`, `local_results`, `shopping_ads`, `related_searches`, ...)
- The response is polymorphic on the `engine` you requested and carries NO type tag in the body. Parse against the engine you asked for.
- Account API: `GET /api/v1/me` — monthly allowance, current usage, remaining credits, `searches_this_hour`, `hourly_rate_limit`
- Analytics API: `GET /api/v1/search_analytics` — per-engine success rate, error rate and latency buckets for your own traffic
- Enterprise: `zero_retention=true` disables logging and storage of the request

## Limits and errors
- Hourly cap: up to 20% of the plan's monthly credits each hour
- NO rate-limit response headers of any kind — no `X-RateLimit-*`, no `RateLimit-*`, no `Retry-After`. Headroom is visible only by polling `GET /api/v1/me`.
- Billing is pay-per-success: only HTTP 200 consumes a credit. One MCP tool call = one credit.
- Errors are a flat `{"error": "<message>"}` JSON body. Not RFC 9457 problem+json, no error codes, no published error reference page.
- Deep pagination: `next_page_token` grows to 8KB+ and will produce HTTP 413 or 414 on a GET. Switch to POST with a JSON body.
- Correlation: every response returns an `x-request-id` UUID header.

## Agents / MCP
- Hosted MCP server: https://www.searchapi.io/mcp (streamable HTTP; remote only — there is no stdio package to install)
- Listed in the official MCP registry as `io.searchapi/mcp`, status active
- Auth: OAuth (recommended) with scope `mcp`, PKCE `S256`, dynamic client registration at https://www.searchapi.io/oauth/register — or a static `X-MCP-Token` header
- Discovery: https://www.searchapi.io/.well-known/oauth-authorization-server and https://www.searchapi.io/.well-known/oauth-protected-resource
- MCP integrations & bundles (max 10 integrations per account): https://www.searchapi.io/integrations/mcp
- Setup: `claude mcp add --transport http searchapi https://www.searchapi.io/mcp`
- 80+ tools; each is the single `search` operation with `engine` pinned to one value
- Blind spot: no MCP tool exposes the Account API, so an agent on MCP alone cannot see its own remaining quota
